Check patient records before you link them

Each record is scored on five dimensions of identity trust, then routed to auto-link, review or quarantine with a plain-language reason. Built for health information exchanges where one identifier can end up shared by different patients.

3. Set thresholds and run

A record's trust score is a weighted mean of five dimension scores (0 to 1). An identifier shared by patients with conflicting details is always quarantined, and a record with any failed check is never auto-linked.

Facility trust (provenance)

How far do you trust each source facility's data? 0 to 1. Records with no facility score 0.5.

Demonstration thresholds and weights only. They are not the validated thresholds from the paper, and the page has not been tested on real patient data.

Audit trail

Every decision is chained to the one before it with a SHA-256 hash, so any later change to a record or decision breaks the chain.

The five dimensions

Completeness: are the core identity fields present? Temporal validity: do birth, admission and discharge dates make sense? Identity consistency: do the identifier format and demographics agree? Provenance: how much is the source facility trusted? Cross-record consistency: does this identifier appear with conflicting details elsewhere?

This page is a browser demonstration of the framework. The full engine, FastAPI service, HL7 v2 intake and audit database are in the repository.
